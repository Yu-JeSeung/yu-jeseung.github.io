# 비속어 필터링 KoELECTRA와 Rule 기반 필터링 적용

## 왜 Rule 기반 필터링을 적용했나

동숲 프로젝트에서 클라이언트가 작성하는 게시글, 댓글, 채팅 내용에서 부적절한 표현을 탐지하고 차단하는 기능이 필요했습니다. 단순히 서버에서 차단하는 것이 아니라, 클라이언트가 어느 부분을 수정해야하는지 알 수 있게 시각적으로 나타내주는 것을 목표로 잡았고, 또한 실시간으로 처리하거나 빠른 응답의 형식을 갖춰야 했습니다.

처음에는 단순히 KoELECTRA 기반 분류 모델만으로 비속어 여부를 판단하는 방식을 고려했지만 변칙적으로 등장하는 금칙어까지 매번 모델 추론을 수행하는 것은 비효율적이라고 판단했습니다. 또한 특수문자나 초성, 띄어쓰기 변형처럼 클라이언트가 의도적으로 우회한 표현을 안정적으로 잡아내는 것도 어려웠습니다.

따라서 금칙어와 우회 표현은 Rule 기반 필터로 먼저 탐지하고, 문맥 판단이 필요한 표현은 KoELECTRA 모델을 통해 추가로 검증하는 구조를 적용했습니다.

## 기존 모델 기반 필터링의 문제점

기존 모델을 추가적으로 계속 학습을 해야한다는 문제점이 있었습니다. 수집된 로그를 기반으로 재라벨링 후 재학습을 진행하였습니다. 이를 주기적으로 반복하는 것도 하나의 해결방법이라 말할 수 있겠지만 담당자가 직접 확인하여 라벨링을 해야한다는 번거로움이 존재했습니다. 또한 모델만으로는 다음과 같은 문제점을 해결할 수 없었습니다.

`1. 우회 표현 문제` : 클라이언트는 비속어를 그대로 입력하는 경우도 있지만 초성, 특수문자, 띄어쓰기, 반복 문자 등을 섞어 표현합니다. 이런 표현 학습 데이터가 충분하지 않으면 모델이 안정적으로 탐지하지 못합니다.

`2.명확한 금칙어 처리의 비효율성` : 금칙어 표현을 목록으로 관리할 수 있는 표현까지 모두 모델 추론에 맡기면 불필요한 연산이 발생합니다.

`3. 예측 결과의 애매함` : 확률 기반으로 결과를 반환하기 때문에 임계값 근처의 문장은 판단의 기준이 모호합니다.

이러한 이유로 모델 기반 필터링은 한계점이 존재한다고 생각했고, Rule 기반 필터링을 추가해 함께 사용하는 구조가 더 적합하다고 판단했습니다.
