포트폴리오를 단순히 프로젝트 목록으로만 두면, 어떤 문제를 발견했고 어떤 기준으로 해결했는지가 잘 보이지 않습니다.

이 블로그에는 앞으로 프로젝트를 만들며 배운 점, 기술 선택의 이유, 실패했던 접근과 다시 고친 과정을 기록하려고 합니다.

## 앞으로 적어볼 글

- LLM호출 비용 감소를 위한 TTL Cache 적용
- LLM 성능 & 속도 트레이드오프 해결법
- FastAPI와 Flask를 선택했던 기준
- RAG, OCR, 추천 시스템을 서비스에 붙이며 배운 점
- 배포와 운영 과정에서 마주친 문제들

작은 기록이라도 계속 쌓이면, 결과물보다 더 선명한 개발자의 흔적이 됩니다.
